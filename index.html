Case Study 01
Agentic Automation

Designing the bridge between AI agents and enterprise automation at scale.

Overview

Agentforce represents Salesforce's most ambitious platform shift — from tools that humans operate to AI agents that act autonomously. I led the design vision for integrating agentic capabilities into Flow Builder, enabling admins and developers to build, test, and deploy AI agents within the same low-code canvas they already know.

The challenge was making autonomous AI behavior feel trustworthy and controllable within an enterprise platform used by millions. We had to answer a fundamental question: how do you give users confidence in something that acts on its own?

Problem

Enterprise customers needed AI agents that could reason, plan, and execute multi-step business processes — but existing automation tools were built for deterministic, human-triggered workflows. There was no way to invoke an agent from a flow, observe its reasoning, or set guardrails on its behavior. Admins felt locked out of the AI conversation.

Solution

We designed a unified workspace where agents and flows coexist. Key design decisions included:

  • Agent invocation as a native Flow element — agents can be called mid-flow with the same drag-and-drop simplicity as any other action, making AI accessible to the 52.8M+ platform users
  • Three interchangeable views — a doc-style editor for plain-language drafting, a low-code canvas for visual design, and a script view for developer control
  • Real-time simulation with debugging — one-click agent testing with transparent reasoning traces so builders can see why an agent made each decision
  • Guardrail configuration — visual controls for defining agent boundaries, escalation triggers, and human-in-the-loop checkpoints

This work shipped as part of Agentforce 360, enabling customers to blend deterministic automation with generative AI reasoning inside a single, trusted platform.

Case Study 02
Low Code Automation Platform

Reimagining Salesforce Flow Builder as the automation platform for 52.8M users.

Overview

Flow Builder is the most powerful declarative tool in the Salesforce ecosystem — and one of the most complex. As Product Architect for Flow & Automation, I led the design evolution of the platform from a process automation tool into a full low-code development environment capable of building reactive applications, orchestrating multi-step business processes, and now invoking AI agents.

My focus was making enterprise-grade power accessible without sacrificing the simplicity that makes Flow the admin's most trusted tool.

Problem

Flow Builder had grown organically over years, accumulating features without a cohesive architectural vision. The canvas was rigid — double-click to edit, no responsive previews, limited debugging. Complex flows became unreadable, and the gap between what Flow could do and what users could figure out was widening. Admins building for mobile, service consoles, and field teams had no way to preview their work in context.

Solution

I drove a multi-release design strategy that systematically modernized the platform:

  • Single-click canvas interactions — replaced double-click editing with direct manipulation, contextual menus, and sticky zoom for a modern builder experience
  • 12-column responsive grid — introduced per-component width control and vertical alignment, giving screen flows true layout flexibility without CSS
  • Reactive screen architecture — designed the interaction model for screens that respond to user input in real-time, eliminating the need for page refreshes or custom components
  • Resizable debug panel — redesigned the debugging experience with card-based execution traces, filtering, search, and clipboard export
  • Screen size preview — added in-canvas device simulation so builders can validate responsive layouts before deployment
  • Flow Orchestration fault paths — designed recovery flows for when steps fail, moving the platform from "happy path only" to enterprise-grade resilience

These shipped across Winter '25 through Summer '26 releases and collectively transformed Flow Builder from an admin tool into a low-code application platform.

Case Study 03
Integration-As-A-Service

Making API-first integration accessible to every team, not just developers.

Overview

MuleSoft's Anypoint Platform is the industry-leading integration platform — but its power came at the cost of accessibility. As Product Architect for MuleSoft (2020-2023), I led the design transformation of the integration experience from a developer-only IDE into a platform that business technologists, admins, and citizen integrators could use alongside professional developers.

The vision: integration as a service that any team could consume, not a bottleneck owned by IT.

Problem

Enterprise integration was trapped in a specialist silo. Building an API or connecting two systems required deep technical knowledge of MuleSoft's Anypoint Studio — a desktop IDE built for Java developers. Business teams waited months for integrations that developers considered low-priority. Meanwhile, shadow IT grew as teams built fragile point-to-point connections outside the platform.

The gap between integration demand and developer capacity was growing 3x faster than headcount.

Solution

I designed a layered integration experience that served multiple skill levels from a single platform:

  • Visual flow designer — a drag-and-drop integration builder with pre-built connectors for 400+ enterprise applications, enabling admins to build integrations without writing code
  • API-first architecture patterns — established reusable design patterns for system, process, and experience APIs that teams could compose like building blocks
  • Anypoint Exchange redesign — transformed the asset marketplace into a discoverable, self-service catalog where teams could find, try, and deploy pre-built integrations
  • Unified monitoring dashboard — designed real-time observability across all integrations with clear health indicators, error routing, and performance metrics
  • MuleSoft Composer — contributed to the design vision for the no-code integration tool that brought MuleSoft's power to business users through a guided, template-driven experience

This work helped position MuleSoft as the integration backbone for Salesforce's broader platform strategy, connecting CRM, commerce, and AI capabilities across the enterprise.

Case Study 04
Watson AI Carbon Design System

Building the design language for enterprise AI at IBM Watson.

Overview

As Sr. Design Manager for Watson at IBM (2016-2018), I led the design team responsible for Watson's analytics and AI experiences. A core part of this work was establishing Watson's visual identity within IBM's Carbon Design System — creating the patterns, components, and interaction models that would define how millions of users experience AI in the enterprise.

This was design at the intersection of data visualization, machine learning, and human trust.

Problem

Watson's AI products had grown rapidly through acquisition and independent development, resulting in fragmented user experiences. Each product — Watson Analytics, Watson Discovery, Watson Assistant — had its own visual language, interaction patterns, and component libraries. Users moving between Watson products felt like they were using entirely different platforms.

Meanwhile, IBM was building Carbon Design System as its enterprise-wide design system, but AI experiences had unique requirements that Carbon's general-purpose components couldn't address — confidence indicators, model explainability, training feedback loops, and data-dense analytical views.

Solution

I led the design effort to create a cohesive Watson experience layer within Carbon:

  • AI-specific component patterns — designed components for confidence scoring, entity recognition highlighting, model training progress, and explainability panels that became standard across Watson products
  • Data visualization system — established a consistent charting and dashboard framework built on Carbon's design tokens, using D3-powered visualizations that scaled from summary KPIs to deep analytical exploration
  • Analytics dashboard architecture — created a flexible dashboard framework with presentation, analytical, and operational views that product teams could compose for their specific use cases
  • AI transparency patterns — pioneered interaction patterns that made AI decision-making visible and understandable, addressing enterprise customers' need for explainable AI before "explainable AI" became an industry standard
  • Cross-product design governance — established review processes and shared Figma libraries that unified the Watson design language while giving individual product teams room to innovate

This work helped establish Carbon as the foundation for IBM's enterprise AI experiences and influenced the later development of Carbon for AI — IBM's dedicated framework for identifying and explaining AI-generated content across all products.
